`aces sdl resolve` now records `local:` imports with a checkout-independent, SDL-base-relative `resolved_source` (POSIX separators) instead of an absolute machine path, so a committed `aces.lock.json` is portable. `aces sdl verify-imports` now passes on any checkout regardless of its absolute path — including CI and other contributors' machines — and fails only when imported content actually changes. Lockfiles generated before this fix contain absolute paths and are treated as stale; re-run `aces sdl resolve` to regenerate them.
